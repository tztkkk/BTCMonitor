# Monitor 产品需求文档

## 1. 产品定位

Monitor 是一个 **Android 金融市场行情 + 策略监控 + 信号提醒工具**。重点不是交易下单，而是让用户无需持续盯盘：App 根据用户预设条件在本地持续监控市场，在重要条件满足时产生信号并发送 Android 通知。

当前产品处于：

```text
可运行 Prototype → 可维护产品
```

当前 v0.3.0 已验证 Android 16 真机运行和多加密资产价格提醒闭环。长期市场与策略范围是产品方向，不代表当前已经支持，也不授权 Developer 在没有 TASK 时实现。

## 2. 用户与核心价值

目标用户是希望关注加密货币、商品、指数或股票，但不能持续盯盘的个人用户。

核心价值：

- 将行情观察条件明确保存为可管理的监控规则。
- 在用户离开 App 后尽可能持续监控，同时诚实呈现 Android/网络限制。
- 条件满足时及时通知，并最终提供可追溯的信号记录。
- 以统一模型逐步扩展指标和策略，而不是为每个策略创建孤立功能。

本产品不承诺行情、信号或通知绝对实时，不构成投资建议。

## 3. 产品核心链路

```text
选择市场
    ↓
查看行情
    ↓
创建监控规则
    ↓
后台监控
    ↓
产生 Signal
    ↓
Android Notification
    ↓
进入 App 查看详情
```

当前真实闭环是“选择内置 OKX 现货标的 → 查看行情/K 线 → 创建价格提醒 → 前台服务监控 → 边沿触发通知”。当前提醒仍区分高于/低于方向；下一阶段会在兼容迁移后统一为双向穿越的“到价提醒”。统一 Signal 实体、信号历史和通用策略尚未完成。

## 4. 市场范围

数据供应商选择是独立技术决策。长期市场范围不得被当前 OKX 实现限制，也不得在 PRD 中假定其他供应商已经确定。

### Crypto

- BTC
- ETH
- 其他可靠数据源支持的加密货币

当前实现：OKX 公开现货的 BTC-USDT、ETH-USDT、SOL-USDT、DOGE-USDT、XRP-USDT。

### Commodity

- GOLD

当前实现：未支持。

### Index

- NASDAQ
- S&P 500
- 其他可靠数据源支持的指数

当前实现：未支持。

### Stock

后续支持；当前未实现。

## 5. 产品模块

### 5.1 首页

长期展示：

- 自选行情和市场概览
- 今日信号
- 正在运行的监控数量与状态
- 快捷创建提醒

当前实现：顶层“行情”页兼具首页职责，展示自选加密资产、价格、24h 涨跌、提醒数量、Service/WebSocket/网络状态，可添加、移除和刷新标的。尚无独立市场概览、今日信号或 Quick Alert 区域。

### 5.2 行情

目标能力：

- 展示 Symbol、Name、Price、Change、Change %、Market Status
- 自选、搜索、分类

当前实现：内置五个 OKX 现货标的的自选增删、价格和 24h 涨跌；没有搜索、分类或跨市场状态模型。

### 5.3 行情详情

目标能力：

- 当前价格、涨跌幅
- K 线与 `1m / 5m / 15m / 1H / 4H / 1D`
- 成交量与指标
- 当前策略状态
- 快速创建提醒

下一阶段明确需求：

- 左右拖动查看历史 K 线。
- 到达已加载历史左边界时自动继续加载更早数据，并保持当前视图位置。
- 双指缩放时间范围。
- 上下缩放价格轴。
- 长按显示十字光标，按住移动时显示所选 K 线时间与 OHLC；松手后保留，点击空白处关闭。
- 十字光标右侧显示“＋”；点击后确认目标价格并填写提醒名称，保存为到价提醒。
- 已有提醒线可以拖动；松手后立即保存新价格并给出反馈。
- 到价提醒属于交易品种，不属于单一 timeframe，在全部周期显示。
- 图表下方继续保留提醒列表，用于修改名称、启停和删除；点击图上的提醒线不打开管理面板。

当前实现：有价格、24h 涨跌、六周期 REST K 线、本地 Canvas 静态 K 线、当前价和提醒价叠加、价格提醒 CRUD。当前没有上述拖动、缩放、十字光标、历史分页或提醒线编辑能力。K 线模型含成交量但 UI 未绘制成交量；没有技术指标和通用策略状态。

### 5.4 策略中心

长期管理：

- Price Alert
- Indicator Strategy
- Price Action
- SMC
- 后续自定义组合策略

当前实现：没有独立策略中心。价格提醒配置位于行情详情；`StrategyEngine` 只支持价格大于等于/小于等于的边沿触发。

### 5.5 信号中心

长期展示：

- 品种
- 时间与周期
- 策略
- Signal Type
- Trigger Price
- Signal Strength
- Status

当前实现：没有统一 Signal 实体、信号中心或历史存储；只有瞬时 `StrategyResult`、通知和诊断日志。

### 5.6 我的

长期管理：

- Settings
- Notification
- Data Source
- Background Monitoring
- Theme
- App 信息

当前实现：“更多”页包含测试通知、行情端点诊断、版本更新、GitHub Release 仓库设置和固定配置；“日志”是独立顶层 Tab。没有完整的设置分组、Theme 切换或数据源选择。

## 7. 当前阶段目标

当前阶段只聚焦以下顺序，不提前实现 Signal Center、Indicator 或复杂 Strategy：

1. 先明确 Market、Chart、Price Alert 的可复用边界，并修复已发现的多标的行情派发正确性问题。
2. 验证成熟 Android/Compose K 线库是否满足交互、扩展、许可证和 Android 16 要求；允许使用独立实验页面，不直接替换生产页面。
3. 建立与 ViewModel、OKX 和持久化模型解耦的可复用交互式 K 线组件。
4. 完成历史拖动/分页、时间与价格缩放、十字光标和 OHLC 查看。
5. 将现有方向提醒安全迁移为双向穿越到价提醒。
6. 完成图上创建、拖动调整提醒，以及全局冷却时间设置。
7. 在 Android 16 真机验证完整闭环后，再由 Planner 选择下一阶段。

## 8. 非功能需求

### 正确性

- 不得因多标的并发、重连或生命周期变化把一个标的的数据错误用于另一个标的。
- 到价提醒在相邻有效 Tick 位于目标价格两侧，或任一 Tick 等于目标价时视为触达/穿越；行情从目标价下方直接跳到上方或反向跳过时也必须触发。
- 提醒是双向穿越，不区分“高于”或“低于”。现有提醒迁移时保留 ID、名称、目标价格和启用状态，移除方向语义。
- 新建提醒或拖动修改价格后，第一条行情只建立基线，不立即通知；之后发生新穿越才通知。
- 所有提醒共用持久化的全局冷却时间，固定选项为 1、5、15、30、60 分钟，默认 5 分钟。
- 冷却期间不发送通知，但继续更新价格位于目标价哪一侧；冷却结束后必须等待下一次新穿越，不按固定时间重复通知。

### 可用性

- Loading、Empty、Error、Disabled 状态必须清晰。
- 后台或通知受系统限制时必须让用户可见，不得宣称“永久在线”。

### 性能与资源

- 多页面和策略复用行情连接；不得为同一数据源无必要建立多个常驻 WebSocket。
- 高频数据进入 UI/策略前需要明确、可测试的采样或聚合规则，且不得造成跨 symbol 饥饿。

### 隐私与安全

- 当前无账号、API Key、下单和静默日志上传。
- 用户分享诊断日志前应能检查内容。
- 更新安装继续执行 SHA-256、包名、versionCode 和签名校验。

## 9. 当前明确不做

除非后续 TASK 明确要求，当前不主动实现：

- 自动交易或 Exchange API Key 交易
- 云端策略服务器或账号云同步
- 用户社交、策略市场
- AI 自动下单
- 完整 SMC 系统
- 完整回测系统
- 为了架构整洁一次性重写现有后台、网络或 UI

## 10. 阶段成功标准

从 Prototype 进入可维护产品阶段至少需要：

- P0 行情正确性问题有自动化测试保护。
- Market、Chart 与 Price Alert 的依赖方向明确，并有可替换的接口或纯模型边界。
- 图表技术选型有可运行 Demo 和 ADR；无合适库时有 Compose Canvas 备用结论。
- 交互式 K 线满足历史拖动/分页、双向缩放、十字光标和 OHLC 查看。
- 到价提醒迁移不丢数据，图上创建/拖动、提醒列表管理和全局冷却规则形成完整闭环。
- 核心修改通过 Build、单元测试和 Android 16 真机矩阵。
